# 동료 검토 진행 가이드

이 문서는 정답을 외우기 위한 답안지가 아니라, 저장소를 함께 보면서 구현 의도와 결과를 빠뜨리지 않고 설명하기 위한 진행 순서다. 각 단계에서 먼저 실제 파일이나 결과를 보여주고, 아래 키워드를 바탕으로 본인의 말로 설명한다.

## 검토 전에 실행할 것

노트북 실행 증거와 검증기까지 확인하는 동료 검토에서는 선택적인 개발 환경을 설치한다. `requirements-dev.txt`가 `requirements.txt`를 포함하므로 두 파일을 따로 설치하지 않는다.

```bash
python -m pip install -r requirements-dev.txt
```

프로젝트 루트에서 다음 명령을 실행한다.

```bash
python -m unittest -v
python -m scripts.run_analysis
python scripts/verify_project.py
```

확인할 결과:

- 단위 테스트 5개 통과
- 분석 파이프라인 정상 종료 및 PNG 7개 생성
- `A1-1 verification passed`
- 실행 완료 노트북의 코드 셀 8개, 오류 출력 0개

의존성 파일을 설명할 때 사용할 구분:

- `requirements.txt`: 과제 실행용 NumPy·Pandas·Matplotlib·Seaborn
- `requirements-dev.txt`: 선택적인 노트북 빌드·검증·원본 Excel 재생성 도구

## 3. DataAnalyzer 구조 따라가기

`src/pipeline.py`를 열고 아래 순서로 이동한다.

1. `load_data()`
2. `handle_missing_values()`
3. `engineer_features()`
4. `detect_outliers()`와 `treat_outliers()`
5. `calculate_rfm()`

각 메서드를 볼 때 설명할 포인트:

- 이 메서드가 하나의 책임만 갖는가?
- 입력과 출력은 무엇인가?
- 다른 데이터나 정책으로 바꿀 때 어느 부분만 교체하면 되는가?
- 독립적으로 테스트할 수 있는가?

파라미터를 볼 때 떠올릴 키워드:

- `outlier_threshold`: 분포와 업무 환경에 따른 조정
- 결측 전략·그룹 열: 데이터셋별 대치 정책
- `reference_date`: Recency 재현성
- `min_rows`, `min_columns`: 입력 데이터 계약

## 5. 벡터화된 특징 공학 보여주기

`engineer_features()`에서 다음 코드를 직접 가리킨다.

- `quantity.to_numpy() * unit_price.to_numpy()`
- `np.stack(...)`
- `mean(axis=1)`과 `std(axis=1)`
- `word_count`

설명에 넣을 키워드:

- Python 행별 반복 없음

- NumPy의 컴파일된 내부 루프

## 10. 대규모 확장 질문 준비하기

고객 100만 명과 1024×1024 이미지가 주어졌다고 가정한다.

설명 전에 계산할 것:

```text
행 수 × 높이 × 너비 × 픽셀당 바이트
```

병목을 찾는 순서:

1. 저장 용량과 네트워크 I/O
2. 이미지 읽기와 디코딩
3. 전체 행렬을 만드는 순간의 RAM
4. Mean/Std 계산 CPU 시간

개선 방향 힌트:

- 배치 처리와 스트리밍
- `uint8` 유지 후 필요한 시점에 변환
- 다운샘플링과 층화 표본
- 반복 특징 사전 계산
- CSV 문자열 대신 바이너리·열 지향 저장
- 프로파일링 후 병렬화
