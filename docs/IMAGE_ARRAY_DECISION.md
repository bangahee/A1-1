# 이미지 배열 사용 결정과 한계

## 1. 문서 목적

이 문서는 A1-1 프로젝트에서 실제 상품 이미지가 포함되지 않은 UCI Online Retail 데이터를 유지하고, `product_image`라는 교육용 배열 필드를 별도로 사용한 이유를 설명한다.

핵심 결론은 다음과 같다.

> 현재 구조는 실제 상품 사진을 분석한 프로젝트는 아니다. 다만 과제의 핵심인 거래 데이터 분석, RFM 고객 세분화, CSV 배열 복구, NumPy Mean/Std 피처 생성과 벡터 연산을 하나의 재현 가능한 파이프라인으로 구현한다. 배열의 출처와 한계를 명시하고, 시각적 의미나 비즈니스 의미를 주장하지 않는다.

## 2. 원본 데이터에 실제 이미지가 없는 이유

프로젝트의 원본은 UCI Machine Learning Repository의 Online Retail 거래 데이터다. 다음과 같은 거래 정보가 포함되어 있다.

- 고객 ID
- 주문번호
- 상품 코드와 상품 설명
- 주문일
- 수량
- 단가
- 국가

이 정보는 고객별 Recency, Frequency, Monetary를 계산하는 데 적합하다. 반면 원본 데이터에는 상품 사진이나 이미지 URL이 포함되어 있지 않다.

실제 이미지가 포함된 상품 데이터셋으로 전체 데이터를 교체하면 이미지 정보는 얻을 수 있지만, 고객 ID·주문번호·구매일·반복 구매 기록이 없어 RFM 분석을 수행하지 못할 가능성이 크다. 따라서 프로젝트의 중심인 고객 거래 분석에 적합한 UCI 데이터는 유지했다.

## 3. 평가항목과의 관계

평가항목은 데이터가 수치형·범주형·날짜형·이미지 중 세 종류 이상을 포함하는지 확인한다.

UCI 원본 데이터만으로 이미 다음 세 가지 실제 데이터 유형을 충족한다.

| 데이터 유형 | 예시 |
|---|---|
| 수치형 | `quantity`, `unit_price`, `amount` |
| 범주형·텍스트형 | `stock_code`, `description`, `country` |
| 날짜형 | `order_date` |

별도의 이미지 관련 항목에서는 배열의 Mean/Std 피처와 텍스트 파생 변수가 생성되었는지를 확인한다. 이 프로젝트는 교육용 배열을 통해 다음 처리 과정을 구현한다.

- CSV 문자열에서 NumPy 배열 복구
- 배열 길이와 유한값 검증
- `np.stack()`을 이용한 행렬 구성
- `mean(axis=1)`을 이용한 상품별 평균 계산
- `std(axis=1)`을 이용한 상품별 표준편차 계산
- Python 행별 반복 대신 NumPy 벡터 연산 사용

따라서 배열 처리와 벡터화라는 기술적 학습 목표는 충족한다.

## 4. `product_image`의 실제 의미

`product_image`는 실제 상품 사진이 아니다. `stock_code`를 안정적으로 해시해 생성한 8×8 크기의 교육용 숫자 배열이다.

결정론적으로 생성했기 때문에 다음 조건을 만족한다.

- 같은 `stock_code`는 항상 같은 배열을 갖는다.
- 표본을 다시 생성해도 같은 결과를 얻는다.
- 값의 범위는 0~255다.
- 64개의 값을 8×8 배열처럼 다룰 수 있다.

하지만 이 배열은 다음 정보를 표현하지 않는다.

- 실제 상품 색상
- 상품 형태나 질감
- 촬영 밝기
- 상품 디자인
- 실제 이미지 품질

따라서 `image_mean`과 `image_std`는 배열 처리 코드의 동작을 확인하는 피처일 뿐, 상품의 실제 시각적 특성을 나타내는 비즈니스 피처가 아니다.

## 5. 배열이 비즈니스 결과를 왜곡하지 않도록 한 방법

교육용 배열은 다음 용도에만 사용한다.

- 배열 파싱 확인
- 동일 길이 검증
- Mean/Std 피처 생성
- NumPy 벡터화 설명
- 메모리 확장 문제 설명

다음 계산에는 사용하지 않는다.

- Recency
- Frequency
- Monetary
- RFM 점수
- 고객 세그먼트
- 매출 분석
- 비즈니스 인사이트
- 마케팅 우선순위

RFM과 비즈니스 제안은 실제 거래 정보인 고객 ID, 주문번호, 주문일, 수량과 단가만을 기반으로 한다. 따라서 교육용 배열이 고객 가치나 매출 결과에 영향을 주지 않는다.

## 6. 코드에서 확인할 수 있는 구현

### 배열 생성

`scripts/prepare_data.py`의 `deterministic_images()`가 상품 코드별 배열을 벡터화해 생성한다.

### CSV 배열 복구

`src/pipeline.py`의 `parse_image_array()`가 문자열 배열을 `float32` NumPy 배열로 변환한다.

```python
cleaned = str(value).strip().strip("[]").replace(",", " ")
return np.fromstring(cleaned, sep=" ", dtype=np.float32)
```

### 배열 검증과 피처 생성

`engineer_features()`는 배열 길이가 모두 같고 비어 있지 않은지 확인한다. NaN이나 무한대가 있으면 오류를 발생시킨다.

```python
image_matrix = np.stack(
    frame["product_image"].to_numpy()
).astype(np.float32, copy=False)

frame["image_mean"] = image_matrix.mean(axis=1)
frame["image_std"] = image_matrix.std(axis=1)
```

이 부분은 Python `for`문으로 각 배열을 처리하지 않고, 하나의 연속된 2차원 행렬에서 벡터 연산을 수행한다.

## 7. 현재 구조의 장점

1. RFM에 필요한 실제 거래 정보를 보존한다.
2. 데이터 출처와 라이선스가 명확하다.
3. 표본과 배열을 동일하게 재생성할 수 있다.
4. 과제에서 요구한 NumPy 배열 연산을 코드로 보여준다.
5. 배열을 실제 이미지라고 잘못 주장하지 않는다.
6. 교육용 배열을 비즈니스 결과와 분리한다.

## 8. 현재 구조의 한계

현재 구조는 다음을 충족하지 않는다.

- 실제 상품 사진 로드
- 실제 이미지의 색상·형태 분석
- 이미지 기반 상품 분류
- 시각 피처와 고객 행동의 관계 분석

따라서 프로젝트를 “실제 상품 이미지를 분석한 프로젝트”라고 소개하면 안 된다.

가장 정확한 표현은 다음과 같다.

> 실제 거래 데이터를 중심으로 분석하고, 이미지 관련 부분은 NumPy 배열 처리와 통계 피처 생성을 검증하기 위한 교육용 필드로 제한한 프로젝트다.

## 9. 실제 이미지로 확장하는 방법

실제 시각 분석이 필요해지면 다음 순서로 확장할 수 있다.

1. 공개 라이선스 상품 이미지 데이터 확보
2. 이미지와 `stock_code` 또는 별도 상품 ID 연결
3. 이미지 크기와 채널 통일
4. NumPy 배열로 변환
5. Mean/Std와 필요한 추가 피처 계산
6. 실제 이미지 출처와 라이선스 기록
7. 기존 교육용 배열 제거 또는 실제 이미지 배열로 교체

대규모 이미지에서는 모든 배열을 한 번에 `np.stack()`하지 않고 배치 처리, 다운샘플링, 바이너리 저장과 사전 피처 계산을 적용해야 한다.

## 10. 동료 검토에서 사용할 답변

### 짧은 답변

> 원본 UCI 데이터에는 실제 상품 이미지가 없습니다. 현재 배열은 이미지 Mean/Std와 NumPy 벡터 연산을 구현하기 위한 교육용 필드입니다. 실제 이미지라고 주장하지 않고, RFM이나 비즈니스 인사이트에도 사용하지 않았습니다. 원본 데이터만으로 수치형·범주형·날짜형 세 가지 유형 조건을 충족하며, 배열은 추가적인 기술 구현을 보여줍니다.

### 자세한 답변

> 실제 이미지를 얻기 위해 데이터셋 전체를 교체하면 고객 ID, 주문번호, 날짜와 반복 구매 기록이 없어져 프로젝트의 핵심인 RFM 분석을 수행하기 어려울 수 있습니다. 그래서 고객 거래 분석에 적합한 UCI 데이터를 유지했습니다. 대신 배열 처리 항목은 상품 코드에서 결정론적으로 생성한 교육용 배열로 구현했습니다. 이 배열을 실제 색상이나 상품 형태로 해석하지 않았고, 고객 세그먼트와 비즈니스 결과도 실제 거래 필드만으로 계산했습니다. 실제 시각 분석이 목적이라면 이후 공개 라이선스 상품 이미지를 상품 코드와 연결해 같은 NumPy 파이프라인으로 확장해야 합니다.

## 11. 최종 판단

현재 구조는 다음과 같이 판단할 수 있다.

| 확인 항목 | 상태 |
|---|---|
| 수치형·범주형·날짜형 3종 이상 | 충족 |
| 배열 문자열 파싱 | 충족 |
| 이미지 형태 배열 Mean/Std 생성 | 충족 |
| NumPy 벡터 연산 | 충족 |
| 실제 거래 기반 RFM | 충족 |
| 실제 상품 사진 기반 시각 분석 | 미구현 |
| 배열 출처와 한계 문서화 | 충족 |
| 배열을 실제 이미지로 과장하지 않음 | 충족 |

따라서 현재 프로젝트는 제공된 세부 평가항목의 배열 처리 요구를 기술적으로 보여주지만, 실제 상품 사진을 분석한 것으로 해석해서는 안 된다. 이 차이를 명확히 설명하는 것이 가장 중요한 검토 포인트다.
